# Style Do & Don't v1.0

## Do
- Open on a slash command being typed (A) or a numbered list + bold hook line (B), in frame 1.
- Keep chrome warm-dark (#1A1A16 / #0C0C10) and use terracotta #D4704C as the only chrome accent.
- Label every demo: lowercase /command or "<topic> explainer" + italic serif "with Claude Code / with one prompt".
- Show a number that moves: views, stats, progress counter.
- Change something every ~1 s; finish a demo in 4–5 s.
- Let the *output* be colourful and textured; keep the frame around it calm.
- End with "Comment “WORD”" + proof grid of everything shown.
- Use real-looking iOS details (9:41, keyboard, reply bar).

## Don't
- Don't start with a logo, title card, or face-only intro without overlay.
- Don't use more than one serif-italic phrase per frame, or serif for whole sentences.
- Don't add gradients/glows to UI chrome; no neon.
- Don't use emoji in UI text or captions.
- Don't let the output card exceed ~82% width except during a deliberate breakout.
- Don't show full sentences as captions — 1–2 words active at a time.
- Don't use white/light app chrome in Family A (light is only for explainer content cards, e.g. R04 L07).
- Don't use generic transitions (spins, cube, page curl).
- Don't omit the CTA or the proof grid.
- For Rishi's brands: don't mix rishi.docx or gradnext styling into this system without a decision (see SKILL.md).
